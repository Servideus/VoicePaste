# Gemini 3.5 Transcribe: настройки и проверка

Дата: 2026-10-04. Приложение и профиль не изменены. Проверены официальные документы, Context7 и реальные ответы REST Interactions API. Секреты в артефакты не записывались.

## Вывод

Специализированная модель быстрая, но текущий `smart` небезопасен для сохранения полного смысла диктовки: обнаружены пропуски целых просьб. Словарь исправил один пример, однако не устранил проблему на новой записи с самоисправлением. Надёжнее исследовать `verbatim`, а сокращение задержки после отпускания кнопки — через Live API. Это кандидаты для следующей реализации, не уже проверенный результат приложения.

## Настройки по официальной документации

- `language_codes: ["ru-RU"]` указывает язык. Отсутствие поля включает определение языка.
- `mode: "smart"` очищает повторы, слова-паразиты и ложные начала, обрабатывает самоисправления и форматирует текст. `mode: {"type": "verbatim"}` сохраняет произнесённое; это режим по умолчанию.
- `custom_vocabulary` предназначен для имён и специальных терминов: до 1000, обычно полезно до 100. Словарь не является инструкцией «ничего не пропускать».
- Thinking не поддерживается: отключать размышления здесь нечего. Обычная дополнительная инструкция в нашем запросе отвергнута с HTTP 400: `Developer instruction is not enabled for this model`.
- В схеме smart нет переключателей для отдельного отключения удаления ложных начал или сохранения отрицаний. Метки времени и разделение говорящих нужны другим сценариям и здесь не включались.

Источники: [Transcribe](https://ai.google.dev/gemini-api/docs/transcribe), [модель](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-transcribe), [схема Interactions](https://ai.google.dev/api/interactions-api).

## Реальные проверки

Время — от начала запроса до полного ответа. В Files-пробе включает загрузку. Записи синтетические; это небольшая диагностическая серия, не равномерный сравнительный бенчмарк.

| Вариант | Секунды | Результат |
|---|---:|---|
| smart + ru-RU, полный сырой ответ | 1,897 | Пропущено «Не отправляй письмо Марии сегодня» уже на стороне API |
| smart как объект `{type: smart}` | 1,682 | Тот же пропуск |
| smart, автоопределение языка | 1,623 | Тот же пропуск |
| smart, словарь «Марии», «резервная копия» | 1,534 / 2,026 | Два ответа сохранили первую фразу |
| smart, словарь VoicePaste/Gemini | 1,369 | Первая фраза сохранена, хотя этих терминов нет в записи |
| verbatim + ru-RU | 1,396 | Полный текст, отрицание сохранено |
| smart со словарём, короткая запись | 1,376 | Полный корректный текст |
| smart со словарём, запись с шумом и фактами | 1,537 | Все факты и отрицания сохранены |
| smart со словарём, новая запись с самоисправлением | 1,372 | Целиком пропущена просьба перенести встречу |
| verbatim, та же новая запись | 1,818 | Полный произнесённый текст |
| smart через Files API | 4,124 | HTTP 429: дневной лимит; качество транспорта не проверено |

Новая запись: «Ну, я хочу перенести встречу на четверг. Нет, на пятницу. В общем, пожалуйста, отправь, отправь Марии новый адрес».

Smart вернул только «Пожалуйста, отправь Марии новый адрес». Verbatim сохранил весь исходный текст, включая четверг, последующее исправление на пятницу и повтор «отправь». Для verbatim эти повторы соответствуют режиму, а не ошибке распознавания.

Словарь действительно изменил ответы на проблемном примере. Почему именно — не установлено; три успеха на одном файле не доказывают исправление потерь в smart.

В этой серии сервер сообщил лимиты Free Tier для проекта: **3 запроса в минуту**, затем **25 запросов в день**. Это точные сообщения текущего проекта, не универсальное обещание квот. Files-проба остановлена после 429; загруженный синтетический файл удалён в finally, процесс завершился без ошибки. Предыдущие 429 нельзя смешивать со скоростью успешного распознавания.

## Практический кандидат

Для проверки сохранения содержания:

```json
{
  "transcription_config": {
    "mode": {"type": "verbatim"},
    "language_codes": ["ru-RU"]
  }
}
```

Добавлять в словарь реальные имена и термины можно по необходимости. Verbatim теряет автоматическую очистку smart; отдельный второй запрос на редактирование добавит задержку и требует проверки сохранения смысла. По текущим данным Gemini 3.5 Flash остаётся проверенным кандидатом для готового оформленного текста.

Live API позволяет передавать PCM mono 16-bit 16 kHz во время записи. Для push-to-talk документирован Manual VAD: отключить автоматическое определение активности, отправить `activity_start` при начале и `activity_end` при окончании. Вставлять нужно финальную транскрипцию, а не промежуточную. Это переносит часть обработки в период удержания кнопки; величина выигрыша, стабильность подключения и доступная квота здесь не измерены. Источник: [Live Transcribe](https://ai.google.dev/gemini-api/docs/live-api/live-transcribe).

Все ответы API сохранены рядом отдельными JSON. Исходный бенчмарк без словаря остаётся действительным для той конкретной конфигурации: [отчёт](../report.md).
